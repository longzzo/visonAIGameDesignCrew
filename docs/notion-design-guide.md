# 노션 디자인 가이드 (정본) — 오너 레퍼런스 준수

> 오너 지시 2026-07-14: "노션 페이지를 만들 때 슬라임 김치 허브(5d04ac9be0928296bb09814235e82f7c) 디자인을 참고하거나 비슷하게".
> 이 문서가 발행 파이프라인(`webapp/server/notion-publish.mjs`)과 편집실·하위 기획서 생성의 **레이아웃 정본**이다.
> 코드를 고치면 이 문서를, 이 문서를 고치면 코드를 같이 — 어긋나면 오너가 본 화면이 정본이다.

## 레퍼런스 해부 (슬라임 김치 허브 실측)

```
**"볼드 피치 한 줄"**
한 줄 설명 문단 (게임을 모르는 사람용)
---
## 게임 개요 (blue)
[2단 컬럼]  개요 표(항목/내용, 5~7행)   |   핵심 문서 페이지 링크 2~4개
---
## 기획서 모음 (blue)
[2단 컬럼]  🟡 콜아웃 "자주 참고할 기획서"   |   ⬜ 콜아웃 "우선순위별 기획서"(링크 목록)
            ⬛ 콜아웃 "완료된 기획서"        |   ⬜ 콜아웃 "작업 중인 기획서"
---
[2단 컬럼]  ## 마일스톤 (blue) + 월별 표    |   ## 참고 (blue) + 링크
(물리 페이지는 맨 아래 1곳 — "Vision Engine 작업실")
```

## 규칙 10조

1. **대시보드 ≠ 문서함.** 허브에는 링크·표·콜아웃만 — 본문 벽글 금지. 물리 페이지는 맨 아래 보관함 페이지 1곳에 모은다.
2. **문서 링크는 반드시 콜아웃 상자 안에** 분류해서 담는다(카테고리당 콜아웃 1개, 첫 줄 볼드 제목). 평면 나열 금지 — 오너가 "가독성 떨어진다"고 지적한 지점.
3. 콜아웃 색 문법: 🟡 yellow_bg=자주 참고/안내 · 기본(무색)=목록 · ⬛ gray_bg=완료/보관 · 🔵 blue_bg=기준 문서.
4. **가로 공간은 2단 컬럼으로** — 개요 표 옆에 핵심 링크, GDD 목록 옆에 명세서·보고서함.
5. 섹션 헤딩은 `## + 파란색` + 섹션 사이 `---` 구분선. 헤딩에 이모지 1개.
6. 개요 표는 **5~7행으로 발췌**(가제·장르·대회·주인공·팀·로그라인) — 정본 테이블 전체 복사 금지(상세는 1장 페이지에 있다).
7. 이미지(키비주얼)는 맨 아래 아트 칸 — 문서 사이에 끼우지 않는다(오너 지시).
8. 링크는 `link_to_page` 블록으로(제목 자동 동기화). 물리 페이지 이동은 공식 API 불가 — Notion MCP `notion-move-pages`만 가능(HANDOFF 함정 21).
9. **API 함정 2건**: ① 한 요청의 중첩은 2단까지 — column_list→column→내용물은 3단이라 컬럼을 자리표시자로 먼저 만들고 내용은 컬럼 id에 2차 append(`appendColumnList` 헬퍼). column_list는 컬럼 2개 이상, 컬럼은 자식 1개 이상 필수. ② **column_list를 `after`로 삽입할 때 그 지점 뒤에 child_page 블록 무리가 이어지면 노션이 무리를 건너뛰어 그 뒤에 꽂는다**(2026-07-14 실측 — 일반 블록은 정상). 처방 = **역순 삽입**: 레이아웃 그룹을 화면 역순으로 각각 `after=앵커`에 삽입 — 컬럼 삽입 시점의 다음 형제가 항상 일반 블록이라 안전하고, 보관함(child_page)은 자연히 맨 아래에 남는다.
10-1. **권한 상속 함정(실사고 2026-07-14)**: 문서 보관함을 허브의 '형제'로 두면 오너가 허브만 공유했을 때 **팀원에게 문서가 하나도 안 보인다**(노션 권한은 하위로만 상속, 링크는 권한을 안 준다). 보관함은 반드시 **허브의 자식**으로 — quirk 회피는 9조 ②의 역순 삽입이 담당한다.
10. 문서 페이지 본문은 기존 규칙 유지: 숫자 소제목 → 볼드 리드 → 불릿/표(notionPolishPrompt·톤앤매너 가이드와 동일).
