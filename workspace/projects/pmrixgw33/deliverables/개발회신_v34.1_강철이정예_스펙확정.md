# [기획 회신] v34.1 강철이 정예몹 스펙 확정 — 구현 보류 해제

## 요청 형식 확답

* **브레스**: 피해 **18 × 1회**(즉발 단일 히트 — 지속·틱 없음), 틱 간격 **해당 없음**, 화염 태그 적용 여부 **○** (해태 석상 −50% 적용, 설한풍 세트 −25%와 **곱연산**, 방어력은 Direct 1회 차감·최소 1 보장)
* **강철이 동시 상주 수**: **1마리**
* **최초 생성 조건**: **18일차 새벽(day 18 시작) 즉시** — 심층 진입 여부 무관
* **생성 깊이/위치 규칙**: **심층 T3 공동(지표 기준 깊이 91~135타일) 무작위** · 경계암(136~140) 생성 불가 · 얼음 호수/제단 **±10타일 회피**(30일 보스 무대 보호) · **플레이어 최소 24타일**
* **처치 후 재생성 조건**: **다음 날 새벽**(1일 1마리 상한)
* **세이브/로드 정책**: **개체 미직렬화**(위치·HP 저장 없음) — 종별 `last_killed_day`(마지막 처치 일차) **정수 1개만 저장**, 로드 시 `현재 day > last_killed_day`면 생성 규칙으로 재생성
* **어둑시니 resident 생성 규칙 동일 적용 여부**: **○ — 같은 시스템, 종별 파라미터만 분리** (어둑시니 16일차~·동시 1마리 / 정예 2종 **상호 최소 12타일**)

## 근거 (질의별)

**① 왜 1회 히트인가 (틱 아님)**
- 정예 특수기 계열(객귀 냉기 AoE 8·구 이무기 '빠직' 18)과 같은 **"예고 1.5초 → 1회 판정"** — 기존 텔레그래프 FSM 재사용, 신규 코드 0.
- **넉백 2가 붙어 있어서** 다단이면 첫 틱에 플레이어가 부채꼴 밖으로 밀려나 이후 틱이 헛칩니다. v33 보스 브레스가 다단(12/초×3초)일 수 있었던 건 넉백 0이었기 때문(bosses.csv 구 행 knockback_tiles=0 확인).
- 1회 히트이므로 multi_hit_defense=first_tick 논점 자체가 소멸 — 일반 Direct 규칙(방어 1회 차감·최소 1)만 적용하면 됩니다.

**① 왜 18인가**
- v34 교체 대칭: 구 이무기 정예의 빠직이 **18**(= 동시점 최상위 잡몹 접촉 16 + 2 원칙)이었고, 강철이가 그 슬롯을 승계.
- 보스 풀히트 36의 정확히 **절반** = "축소판" 서사 일치. v33 보스 수치 상속(36)은 정예 HP 2,800에 과도해 기각.
- 구현 표현(BossDefinition식): tele 1.5 / Cone / range 3 / arc 60 / dmg 18 / duration 0 / tick 0 / knockback 2 / cd 12 / fire_tag 1. duration·tick 0 = 기존 즉발 처리 경로 그대로.

**②~⑤ 생성·재생성**
- "상주(resident)"의 정의 = 그곳에 산다 → **플레이어 진입 트리거(lazy) 기각**, 일차 기준 고정 생성이 단순하고 세이브 정합도 쉽습니다.
- 깊이 91~135는 globals `layer_t2_depth`(90)·`layer_t3_depth`(135) 정본에서 도출. VE 회의의 "d136~140"은 **경계암(bedrock) 구역이라 기각**, "Y=−12"는 정본 좌표계에 존재하지 않는 날조라 기각.
- 재생성 "다음 날"인 이유: 역린·가뭄 심장은 소비처가 각 1개(서리발톱 장갑·한파 코어)라 **잉여가 나도 경제가 안 무너집니다**(v33 보스 재소환도 반복 드랍이었음). 대신 눈물 4 반복 수급·도감 킬 카운트·재도전 재미를 보존. 1일 1마리 상한이라 어뷰징 불가.
- 최소 거리 24타일 = 기존 밤 스폰 최대 거리(코디네이터 12~24)의 상한 재사용 — 화면 밖 보장.

**⑥ 세이브**
- `boss_save_policy=no_serialize`의 취지(활성 개체 직렬화 금지) 준용. 위치·HP·상태를 저장하는 순간 로드 정합 버그 표면적이 커지므로 **일차 플래그 1개**로 축소. "처치 → 저장 → 로드 → 당일 재파밍" 어뷰징도 이 플래그가 차단합니다.

**⑦ 어둑시니**
- 정본이 이미 "어둑시니 상주와 같은 로직"을 명시(GDD 6-9) — 이번에 그 로직의 실체를 정의한 것이므로 어둑시니가 같은 시스템을 쓰는 게 정본 이행입니다. 종별 값만 CSV/globals로 분리.
